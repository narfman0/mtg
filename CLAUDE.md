# MTG workspace

- My decks live on Moxfield (source of truth); `decks/` holds cached snapshots, one file per deck (e.g. `decks/satoru.txt`), in plain decklist format: `<count> <Card Name>` per line — mainboard, blank line, commander(s), then a section per Moxfield tag: `# Proxies` (deck cards carrying the `proxy` tag — a subset of the list above, not extra cards), `# Purchased` (cards tagged `purchased` — bought, but not necessarily arrived; ones marked `[considering]` are still in the mail and not in the deck yet), `# Tagged <tag>` for any other tag (`printme` is one: cards to print as proxies alongside the `proxy` ones), and `# Considering` (the Moxfield maybeboard; candidates, not part of the deck). `python3 sync_decks.py --tag printme` lists every card carrying a tag across the cached decks without syncing.
- When I ask about "my deck" or a deck by name, refresh the cache with `python3 sync_decks.py` (deck name → Moxfield ID mapping is in that script), then read the matching file in `decks/` — don't ask me to paste the list. The script auto-commits and pushes deck changes, building a deck history in git. If Moxfield is unreachable, use the cached file and tell me it may be stale.
- When I say I've changed a deck, re-sync to pull the change from Moxfield. Don't hand-edit deck files (sync overwrites them); if my change isn't on Moxfield yet, remind me to make it there first.
- Proxy printing goes through `python3 print_proxies.py <file.pdf>` (Epson ET-8500) — it forces true 100% scaling and picks the media type that selects the right black (matte pigment vs photo dye). `-p` names the stock loaded in the rear tray and is mandatory — `-p vinyl` for matte vinyl sticker sheets. `--test` prints one page on plain paper to check layout before spending stock.
- EDHREC data is cached offline in `edhrec/` (gitignored). Refresh with `python3 sync_edhrec.py [--cards] [--themes]`; query it with `python3 edhrec.py <commander|rec|cuts|avg|card|theme|list> <deck>` — never hit edhrec.com directly when the cache has the page.
- The Scryfall card data in `oracle-cards.jsonl` is gitignored and refreshed with `python3 sync_cards.py` (no-op if under a week old; `--max-age 0` to force a check). It diffs each refresh against the committed `cards-status.json` and reports Commander bans, unbans, and Game Changer list changes — tell me about those.
- I work from three computers. The card file is too big to commit, so `cards-status.json` is the shared version pin: commit it after a refresh, and on the other machines `sync_cards.py` sees it's behind and pulls the same Scryfall build down. Don't propose committing `oracle-cards.jsonl` — it's over GitHub's file limit and undeltifiable.
- Card lookups and rules questions go through the mtg skill (offline oracle database + Comprehensive Rules) — never from memory.
- Custom proxy rendering (own frame, own set numbering, MPC Autofill releases) lives in the separate `tcg-mint` repo (`~/workspace/tcg-mint`, github.com/narfman0/tcg-mint). Point it at this card file with `MINT_CARDS=~/workspace/mtg/oracle-cards.jsonl` rather than downloading a second copy.
- One branch: `main`. Commit deck and script changes straight to `main` and push every time — no feature branches, no PRs, no leaving commits sitting locally (I pull `main` from three machines, so an unpushed commit is an invisible one). If you're working in a git worktree, `git push` fails with no upstream: push with `git push origin HEAD:main` instead of creating a branch for it.
